  HFL-MM, defined in SIMULATORS/model/architecture/hfl_mm_model.py.

  is designed but not wired into the training path is marked as such

  SECTION 1: THE FOUR HARD CONSTRAINTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The architecture is not a free choice. Four constraints bind it
simultaneously, and each one eliminates otherwise-attractive options.

  CONSTRAINT 1 — Inference under 100 ms on edge hardware (Objective 3)
    Eliminates ViT, ResNet-50, EfficientNet-B7 and transformer language
    backbones. Admits small 1D convolutional stacks, GRUs, MobileNet-
    class image networks and MLP feature encoders.

  CONSTRAINT 2 — DP-SGD compatibility
    Opacus computes PER-SAMPLE gradients. BatchNorm makes each sample's
    output depend on the other samples in its batch, so a per-sample
    gradient is not well defined and the privacy accounting is invalid.
    Every normalisation layer is therefore GroupNorm.

    This is enforced, not merely intended: build_hfl_mm_hc() walks the
    constructed module tree and RAISES if any BatchNorm survives. A
    silent BatchNorm would surface much later as an opaque Opacus
    validation error, or worse, not at all.

  CONSTRAINT 3 — Two heterogeneous modalities
    One branch consumes a multi-channel time series; the other consumes
    either an image or a dense feature vector, depending on dataset.
    The two cannot share an encoder.

  CONSTRAINT 4 — Small enough to transmit every round
    The uplink objective (>= 50 % reduction) is a property of what is
    SENT, not of what is stored. This drives the freeze-and-compress
    design in Sections 3 and 4.

  SECTION 2: HFL-MM ARCHITECTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  modality A ──> encoder_a (FedMamba-HC) ──> 256 ─┐
                                                   ├─> LateFusionHead
  modality B ──> encoder_b ─────────────> 576 ─────┘        │
                                                            v
                                                        n_classes

2.1  encoder_a — FedMamba-HC

  A stacked 1D convolutional front end followed by a bidirectional GRU
  over the temporal axis, with GroupNorm throughout. Input channel
  count is a CONSTRUCTOR ARGUMENT (n_channels_a), never a constant, so
  the same class serves an 18-channel intraoperative trend tensor and a
  12-channel inertial tensor without modification.

  Output: 256-dimensional embedding.

2.2  encoder_b — modality-B encoder, selected by the registry

  modality_b = "features"  → FeatureEncoder: in_dim → 1024 → 576 MLP
                             with GroupNorm. Used for both current
                             datasets (34-d clinical vector, 2048-d
                             video features).
  modality_b = "image"     → MobileNetV3 backbone, retained in the code
                             for image modalities. Not exercised by
                             either current dataset.

  Output: 576-dimensional embedding.

2.3  LateFusionHead

  Concatenate(256, 576) = 832 → 512 → 256 → n_classes, GELU
  activations, GroupNorm, dropout 0.3.

  WHY LATE FUSION AND NOT CROSS-ATTENTION
    Late fusion keeps each encoder independent until the final head.
    That property is what makes the privacy design in Section 3
    possible at all: the head is a small, self-contained block that can
    be frozen away from, or trained separately from, the encoders. A
    cross-attention design entangles the two streams throughout the
    network, so there is no small separable block left to DP-train.

2.4  MEASURED PARAMETER COUNTS

  ┌──────────┬────────────┬───────────┬───────────┬────────────────────┐
  │ dataset  │ total      │ encoder_a │ encoder_b │ head (DP-trained)  │
  ├──────────┼────────────┼───────────┼───────────┼────────────────────┤
  │ vitaldb  │ 1,864,227  │ 674,913   │ 629,440   │ 559,874  (30.0 %)  │
  │ wear     │ 3,925,875  │ 670,113   │ 2,691,776 │ 563,986  (14.4 %)  │
  └──────────┴────────────┴───────────┴───────────┴────────────────────┘

  The head is roughly the same absolute size in both cases; the
  percentage differs because WEAR's 2048-dimensional input makes
  encoder_b large. The transmitted fraction is therefore a property of
  the dataset, not a tunable claim, and is reported per dataset.

  SECTION 3: THE PRIVACY DESIGN — HEAD-ONLY DP FINE-TUNING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

3.1  THE PROBLEM

  A strict budget forces a large noise multiplier. Training a full
  multimodal network from scratch under that noise destroys the
  encoders' gradients before they can form useful features: the
  encoders never learn, so the head has nothing to work with, and the
  system collapses toward chance.

3.2  THE MECHANISM

  1. Pretrain both encoders non-privately (pretrain_encoders.py).
  2. FREEZE both encoders.
  3. DP-train ONLY the fusion head, federated across clients.

  Why this survives the same noise: a small head over frozen, already-
  discriminative features is close to a linear probe — a low-
  dimensional, well-conditioned problem that DP-SGD optimises robustly.
  Training encoders from scratch under the same sigma is not.

3.3  THE POINT THAT IS EASIEST TO MISREAD

  FREEZING DOES NOT REDUCE THE NOISE.

  Sigma is a function of the privacy budget, the number of steps and
  the sampling rate. It does not depend on how many parameters are
  being trained. Freezing changes the OPTIMISATION GEOMETRY so that the
  same sigma becomes survivable — it does not buy a weaker guarantee.

  This distinction is the whole claim, and it is written into the code
  comments so that a reader of either the thesis or the source cannot
  come away thinking the budget was quietly loosened.

3.4  AN IMPLEMENTATION HAZARD, DOCUMENTED

  requires_grad is NOT part of state_dict. Every rebuild or reload of
  the local model in the federated loop must RE-APPLY the freeze, or
  the encoders silently become trainable again and the guarantee no
  longer describes what ran. freeze_encoders() is therefore called
  after every load in the training loop, not once at setup.

3.5  ACCOUNTING

  One sigma is precomputed for the whole budget and ONE persistent
  privacy engine per client is reused across every round. Calling the
  accountant afresh each round would drop cross-round composition and
  report a budget far smaller than the one actually spent.

  The conformal calibration step (Section 5) also consumes budget and
  is composed into the reported total. A privacy claim that counts only
  the training term is incomplete.

3.6  A LIMITATION STATED PLAINLY

  If the encoders are pretrained on the pooled federated training data,
  they have seen private data non-privately. Numbers obtained that way
  measure the UPPER BOUND of what head-only DP can achieve; they are
  not a valid end-to-end guarantee. pretrain_encoders.py prints a loud
  PROXY/ORACLE warning in that mode and stamps the mode into the
  checkpoint metadata.

  A defensible guarantee requires --public_data: a disjoint index set
  no client ever trains on. The script refuses the flag if the supplied
  indices intersect any client's training data. Closing this gap with a
  genuinely external public corpus is the single most important
  outstanding item in the privacy story.

  SECTION 4: WHAT TRAVELS ON THE UPLINK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Compression chain, applied to the head delta:

    top-k sparsification, keep 20 %   → nominal 5x
    8-bit quantization                → nominal 4x
    error feedback                    → residual carried to next round
                                        so dropped coordinates are not
                                        lost, only delayed

  Under frozen encoders the encoder deltas are exactly zero. A fixed-k
  top-k selector will nonetheless "select" 20 % of an all-zero tensor
  and transmit those zeros as if they were updates. The selector is
  therefore capped by the number of non-zero entries, so an all-zero
  tensor sends nothing. Without that cap the measured uplink is
  inflated by traffic that carries no information.

  The dense (non-frozen) path is unaffected by the cap and was verified
  bit-identical before and after the fix.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  SECTION 5: FedConform-HC — CALIBRATED PREDICTION SETS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Status: IMPLEMENTED (model/utils/fedconform_hc.py).

  A point prediction is insufficient for a clinical decision. Split
  conformal prediction converts model scores into a set that contains
  the true label with a user-chosen probability, using a held-out
  calibration split. The federated version aggregates a per-client
  quantile hierarchically.

  THE DP MECHANISM MATTERS HERE
    The quantile must itself be released privately. An additive noise
    mechanism on a quantile is a poor fit: the noise scale needed for a
    strict budget is comparable to the spread of the statistic, so the
    released quantile is dominated by noise and the resulting sets are
    either vacuous or invalid.

    The implementation uses the EXPONENTIAL MECHANISM, which selects a
    value from the score distribution with probability weighted by
    utility, rather than perturbing the value additively. Measured on
    calibration data, the exponential mechanism's bias was ~0.001
    against an additive mechanism's standard deviation of ~0.416 on the
    same statistic — three orders of magnitude better behaved.

  BUDGET: calibration runs on the final round only, and its epsilon is
  composed into the reported total rather than reported separately.

  SECTION 6: HIERARCHICAL TRAINING LOOP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Layer 1  client       local DP-SGD on the head; compress the delta
  Layer 2  edge (x2)    FedAvg over its clients every tau_e rounds;
                        ASWA staleness weighting
  Layer 3  cloud        FedAvg over edges; redistribute

  MODEL SELECTION
    On a POOLED validation split across all clients, never on a single
    client's split. One client's split is small and class-skewed enough
    that a handful of misclassifications swings the score by points, so
    selecting on it selects noise. Selection metric is AUPRC for binary
    tasks and macro AUROC otherwise.

  ABLATION KNOBS (all exposed as flags, used by the Phase 6 ablation)
    --n_edges / --tau_e   hierarchy
    --no_dp               privacy off, genuinely: no clipping, no
                          noise, no accountant. This is NOT the same as
                          a large epsilon, which still clips per-sample
                          gradients and therefore measures a loose
                          budget rather than the absence of privacy.
    --sparsity            top-k fraction
    --quant_bits          quantization width

  THE THREE ROWS THAT NEED ACTION

  ASWA runs in every hierarchical configuration, so its effect is baked
  into those results and cannot be separated from them. To claim it, an
  arm is needed that is identical to the full system except that
  staleness weighting is replaced by uniform sample-count weighting,
  paired by seed. Until that arm exists ASWA is an implementation
  detail, not a result.

  FedKD-E must be restricted to trainable parameters before it can run
  at all under the head-only recipe: as written it would update frozen
  weights, breaking both the freeze and the privacy accounting that
  assumes it. It stays disabled until that fix lands.

  ClinicalCMGA is not built and is not planned, for the architectural
  reason in Section 3: cross-attention entangles the modality streams
  and leaves no small separable head to DP-train, which would forfeit
  the head-only recipe. It is a documented design alternative, not a
  component of this system.

  SECTION 8: DEPLOYMENT PATH
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The trained checkpoint is exported to ONNX, giving a runtime-
  independent artifact whose input shapes and class count are read FROM
  THE GRAPH by the benchmark rather than assumed by it.

  GroupNorm requires a shim for ONNX export; it is applied at export
  time only and does not alter the trained weights.

  INT8 dynamic quantization is available but OPT-IN and non-fatal.
  ONNX Runtime decomposes Gemm into MatMul before quantizing, so
  node-exclusion by the original layer name does not match the rewritten
  node, and the resulting graph can fail to load. Rather than ship a
  model that silently fails on some runtimes, INT8 is offered as an
  option and its failure never blocks the FP32 path.

  The latency figure must state its execution provider. The IoT
  deployment claim is a CPU claim; measuring on CUDA benchmarks the
  edge server instead, which is a different question.
