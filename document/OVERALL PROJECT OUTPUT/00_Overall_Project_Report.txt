  WHAT THIS DOCUMENT IS

  This is the EXECUTION PLAN for the study: what is built, how it will
  be run, and what each experiment will establish. It is not a results
  report — the results are produced by running the pipeline it
  describes.

  Where a number already exists it is quoted and its artifact named.
  Where an experiment is designed but not yet run, this document says
  what it will measure and what outcome would count as meeting the
  objective — so that when it runs, the answer is already defined and
  cannot be chosen after seeing the data.

  Fixing the target before the run is the point. An objective whose
  pass condition is written down in advance cannot be quietly relaxed
  to fit whatever came out.

  PROBLEM
    Multimodal IoT devices generate large, heterogeneous data that
    overloads networks and risks privacy when centralised. Transmitting
    raw streams to the cloud increases latency and energy use, harming
    real-time decisions. On-device models reduce transfer but struggle
    to stay accurate and coordinated across devices. A hierarchical,
    privacy-preserving approach is needed that balances local
    computation, communication, latency and energy across edge-cloud
    layers.

  OBJECTIVES (quantified, as written in the source)
    O1  Hierarchical FL design   >= 50 % reduction in uplink traffic
    O2  Privacy mechanisms       strict budget eps <= 1, with model
                                 accuracy loss limited to <= 2 %
    O3  QoS validation           inference latency < 100 ms AND
                                 > 99 % successful model updates
    O4  Energy efficiency        >= 20 % energy saving per training
                                 round

  These thresholds are encoded in exactly one place in the codebase,
  SIMULATORS/scripts/check_objectives.py, so a target cannot drift
  between a script, a figure and the thesis text.

  vitaldb  PRIMARY — clinical IoMT
           48,712 windows from 6,257 surgeries, 9 clients (surgical
           type), binary postoperative ICU admission (19.7 % positive).
           Modality A: (18, 300) intraoperative trends + observed-masks
           at 0.5 Hz. Modality B: (34,) preoperative clinical vector.
           Pairing: same patient, same second, one acquisition system.
           Split: by case, stratified within surgical type.
           Client ICU base rate spans 3.2 %-50.7 % — genuinely non-IID
           by clinical specialty, not by a chosen Dirichlet parameter.

  wear     FAST ITERATION — wearable IoT
           38,578 windows, 22 subjects, 18 activities.
           Modality A: (12, 100) inertial at 50 Hz.
           Modality B: (2048,) egocentric video features, same 2 s.
           Pairing: hardware-synchronised.
           Split: temporal within (subject, activity) with a boundary
           gap, so no overlapping window crosses a split.

  Full detail: document/DATASET & MODEL GUIDE/01_Datasets.txt

  Both are audited by an 8-category adversarial verifier
  (tests/verify_datasets.py) covering split disjointness, subject and

  SECTION 5: THE ONE HEADLINE RESULT THAT IS MEASURED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  MULTIMODAL FUSION HELPS — VitalDB, centralised, non-private, 2 seeds

    arm                AUROC       AUPRC    case AUROC   case AUPRC
    signals only      0.8283      0.5281       0.8590       0.6446
    clinical only     0.7700      0.5022       0.7713       0.4961
    FUSED             0.8694      0.6343       0.8875       0.6740

    Gain over the BEST unimodal arm: +0.0411 AUROC, +0.1062 AUPRC,
    which is 14.1x the across-arm seed standard deviation.

  Why this is the right test: fusion beats BOTH modalities, not merely
  the weaker one. A fused model can match the weaker arm by ignoring
  it; beating the stronger arm is the only outcome that requires the
  second modality to contribute. Each arm is retrained on its own
  inputs rather than fed zeros, so the comparison measures what a
  modality is WORTH rather than what happens when it breaks. The test
  is centralised and non-private so the answer is about the DATA and
  not confounded by federation or privacy noise.

  WEAR is AT CEILING and does not corroborate this. Its best single
  modality already reaches 0.9976 AUROC, leaving no headroom for a
  second modality to fill; the +0.0004 gain there is reported as a
  ceiling effect, not as supporting evidence. The multimodal claim
  rests on VitalDB alone, and the ablation script writes this verdict
  into its own output so it cannot be misread downstream.

  Artifact: results/phase5/ablation_vitaldb.json

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  will settle it is fixed in advance.

  ┌───────┬────────────────────────┬───────────┬──────────────────────┐
  │ Obj.  │ Pass condition         │ Owner     │ Produced by stage    │
  ├───────┼────────────────────────┼───────────┼──────────────────────┤
  │ O1    │ uplink reduction ≥50 % │ NS-3      │ ns3_network          │
  │ O2a   │ epsilon ≤ 1            │ training  │ proposed             │
  │ O2b   │ accuracy loss ≤ 2 pp   │ eps sweep │ epsilon_sweep        │
  │ O3a   │ P95 latency < 100 ms   │ ONNX      │ inference_bench      │
  │ O3b   │ update reliability>99 %│ NS-3      │ ns3_network          │
  │ O4    │ energy saving ≥ 20 %   │ CloudSim  │ cloudsim_energy      │
  └───────┴────────────────────────┴───────────┴──────────────────────┘

  HOW EACH ONE WILL BE MEASURED

  O1  From MEASURED compressed uplink bytes, not from a nominal
      compression ratio. The reduction is computed against the
      centralised arm on the same data and topology.

  O2a Read from the live privacy accountant at the end of training,
      composed across rounds and including the conformal calibration
      budget. A system that reports only its training term has
      understated what it spent.

  O2b A PAIRED comparison — same model, same data, same seed, privacy
      on versus off. The epsilon sweep produces both the private points
      and the no-DP reference, so the loss is a paired difference and
      not a comparison against a number from a different setting.

  O3a Through a portable runtime on an exported graph, with the
      execution provider stated. The deployment claim is a CPU claim;
      measuring on GPU answers a different question.

  O3b PER UPDATE, not per run. The objective asks about a model update.
      The whole-run compound (per-update raised to the number of
      rounds) is a different quantity that decays fast enough to make a
      healthy per-update rate look like a failure.

  O4  From the CloudSim host power model, with GPU overhead charged to
      EDGE servers only — end devices here are embedded-class and have
      no GPU, so charging GPU power to them would inflate the baseline
      and therefore the saving.

  The thresholds live in exactly one place, scripts/check_objectives.py,
  which scores all six and names the artifact behind each number. Where
  an experiment has not yet run it reports NOT MEASURED and names the
  stage that would settle it — it never reports FAIL for an unrun
  experiment, and never PASS from a default.

    python scripts/check_objectives.py --dataset vitaldb

  SECTION 7: EXPERIMENTAL DESIGN — HOW THE CLAIMS WILL BE SEPARATED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

7.1  BASELINES B0-B6

    B0  Centralized        pooled data, no FL, no DP    — upper bound
    B1  Local only         no federation                — lower bound
    B2  FedAvg             FL, no privacy
    B3  FedProx            + heterogeneity handling
    B4  DP-FedAvg          flat FL + DP on the WHOLE model
    B5  MOON               + model-contrastive
    B6  DP-FedAvg-Head     flat FL + DP on the FUSION HEAD only

    B6 is not from the literature. It exists to remove a confound: the
    proposed system differs from B4 in TWO ways at once — it adds the
    edge tier AND it restricts DP to the head over frozen encoders.
    Comparing only B4 against the proposal cannot say which change
    earned the result.

      B4 → B6    isolates the value of head-only DP  (recipe)
      B6 → HFL   isolates the value of the edge tier (topology)

    B4 and B6 consume the SAME budget and the SAME sigma. Freezing does
    not buy a weaker guarantee; it changes the optimisation geometry so
    the same noise becomes survivable.

7.2  FIVE-SYSTEM COMPARISON

    S0 Centralized · S1 Flat FL no DP · S2 flat FL + DP ·
    S3 hierarchical WITHOUT DP · S4 proposed

    S3 is the second half of the same decomposition: it holds the
    topology of S4 while removing privacy entirely, so S3 → S4
    measures what privacy costs at fixed topology.

    S3 uses a genuine no-privacy path (no clipping, no noise, no
    accountant), NOT a large epsilon. A loose budget still clips
    per-sample gradients, so it measures a weak guarantee rather than
    the absence of privacy, and would understate DP's true cost.

7.3  COMPONENT ABLATION A0-A5

    Remove one component at a time from the full system:
    C1 hierarchy · C2 differential privacy · C3 sparsification ·
    C4 quantization · C5 multimodal fusion.

    Each arm is a single training invocation with one flag changed, so
    an ablation arm cannot drift from the system it is ablating.

7.4  STATISTICS

    Contrasts are PAIRED by seed — two arms at the same seed share
    data order and initialisation, so the seed is a blocking factor and
    an unpaired test discards it. Intervals are Student-t, because at
    3-5 seeds the normal approximation is materially too narrow.
    Verdicts are driven by whether the confidence interval contains
    zero, not by a p-value alone. The target is >= 5 seeds; runs with
    fewer are reported with their n and flagged as underpowered.

  These are recorded because a thesis that reports only its successes
  is not reporting its work.

    Adaptive per-layer privacy allocation
      Implemented and compared against a uniform budget. Measured
      WORSE than uniform. The additional composition it incurs across
      parameter groups outweighs the benefit of allocating noise
      unevenly. Reported as a negative result, not quietly dropped.

    Personalised local adaptation
      Implemented; measured no meaningful effect on the tested
      configuration.

    Edge-side knowledge distillation
      Implemented but NOT freeze-aware: it does not account for frozen
      encoders, so it is disabled in every reported run. Until it is
      made freeze-aware it contributes nothing and is not claimed.

    Cross-modal gated attention
      DESIGNED ONLY. No reference from the training path. It is not a
      contribution of this work and is listed in the component status
      table as design-only so it cannot be mistaken for one.

  These must be re-measured on the current datasets before any of the
  above is restated as a finding for this thesis.

  L1  ENCODER PRETRAINING PROVENANCE — the largest open item.
      If encoders are pretrained on the pooled federated training data,
      they have seen private data non-privately, and the resulting
      epsilon is an UPPER BOUND on what head-only DP can achieve rather
      than a valid end-to-end guarantee. A defensible claim needs a
      genuinely external public corpus or a disjoint public split. The
      tooling supports this (--public_data, with an overlap check that
      refuses intersecting indices); the corpus is not yet in place.

  L2  WEAR CANNOT EVIDENCE FUSION. It is at ceiling. It is a pipeline
      and iteration dataset, and is described as such everywhere.

  L3  SEED COUNT. Target is >= 5 seeds per configuration; current
      ablation evidence uses 2. The statistics tool flags every point
      that falls short rather than reporting it as if it were powered.

  L4  ASWA IS UNABLATED. It is implemented and runs, but its effect
      has not been isolated, so it is not claimed as a contribution.

  L5  CLOUDSIM ARGUMENT INTERFACE unverified, so Objective 4 will
      report NOT MEASURED until that stage is wired and run.
